# 简历润笔 ResumePolish — 测试实例集

> 用途：验收 V1.0 交互流程、校验规则与边界处理（Mock 演示模式，无需 API Key）。
> 服务：`http://localhost:8787`（本机 `npm start` 启动，无 Key 自动进入 Mock 模式）。
> 注意：Mock 输出是**确定性模板**，不反映真实模型质量；本文档测的是「流程与规则」，不是「文采」。

---

## 0. 准备工作

### 方式一：浏览器（推荐，最直观）
打开 `http://localhost:8787`，在「经历」「JD」两个框粘贴内容，点「生成」。
页面下方会展示四要素：改写文案 / 逐处修改对照（含理由）/ 岗位关键词命中 / 追问。
回答追问后点「补充并重新生成」可走完整闭环。

### 方式二：命令行（看原始 JSON）
```bash
curl -s -X POST http://127.0.0.1:8787/api/rewrite \
  -H "Content-Type: application/json" \
  -d '{"experience":"...","jd":"...","followups":[...]}'
```
健康检查：`curl -s http://127.0.0.1:8787/api/health` → `{"status":"ok","mock":true}`

## 1. 正常路径

### 1.1 标准改写（四要素齐全）
- **经历**：`在某电商公司运营岗实习，负责信息流投放`
- **JD**：`运营实习生：投放优化、数据分析`
- **预期**：HTTP 200，返回 `rewritten`（改写文案）、`diff`（逐处对照带理由）、`keywords`（关键词 hit/missing）、`questions`（追问），且 `mock_mode: true`。

### 1.2 带小数的经历（曾经是 500，见 Issue #20）
- **经历**：`在某电商公司运营岗实习，负责信息流投放，预算 3.2 万元，ROI 1.8`
- **JD**：`运营实习生：投放优化、数据分析`
- **预期**：HTTP 200，`rewritten` 中 `3.2` 完整保留（不被小数点切断）。

### 1.3 追问补充闭环（曾经答案被丢弃，见 Issue #19/#23）
第一步，**不带** followups：
- **经历**：`在校园公众号写过几篇推文`
- **JD**：`内容运营实习：内容生产、数据分析`
- **预期**：`rewritten` 出现「可量化成果为待补充」，`questions` 含一条「这段经历带来的可量化结果是多少？」

第二步，**带上**答案：
```json
"followups":[{"question":"这段经历带来的可量化结果是多少？","answer":"6 篇，阅读量 1200，平均 400，涨粉 80"}]
```
- **预期**：`rewritten` 出现 `6 篇、1200、400、80`（全部数字都被消费），`questions` 为空（已答不再追问）。

## 2. 输入校验（曾经报错的边界）

| # | 输入（experience） | 曾经的 bug | 现在预期 |
|---|---|---|---|
| 2.1 | `。` / `！！！` / `，，，` | 500（Issue #22） | 400「仅标点、符号或表情无法改写」 |
| 2.2 | `🎉` / `￥` / `……` | 500（Issue #22 扩展） | 400（同上文案） |
| 2.3 | `与、和` / `的了和` | 500（Issue #34） | 400「仅有标点或虚词无法改写」 |
| 2.4 | 空 / 纯空白 | 400（正确） | 400「请粘贴一条简历经历」 |
| 2.5 | 超过 300 字 | — | 400「经历不能超过 300 字，请拆分成多条」 |

> 2.1–2.3 是关键回归点：这三类输入都能「骗过」简单的 trim 判断，却会在下游校验炸成 500。
> 现在统一在输入层拦成 400，且给出可理解的引导文案。

## 3. 关键词提取（真实招聘启事形态）

### 3.1 句子型 JD（曾经产出「岗位职责」「AB」等垃圾词，见 Issue #29）
- **经历**：`在某电商公司运营岗实习，负责信息流投放`
- **JD**：`岗位职责：1. 负责信息流投放，对投放 ROI 负责；2. 设计并执行 A/B 测试，输出数据复盘。任职要求：1. 本科及以上，数据敏感；2. 会用 Excel 与 SQL 优先`
- **预期**：`keywords` 来自 JD 能力章节，**不含**「岗位职责」「任职要求」「AB」这类章节标题或残片。修复后示例：`投放, 测试, ROI, SQL, 数据敏感`。

### 3.2 英文工具名不被割裂（曾经拆成 Google+Analytics，见 Issue #40）
- **JD**：`岗位职责：熟练使用 Google Analytics 与 Final Cut`
- **预期**：`keywords` 含完整工具名 `Google Analytics`、`Final Cut`，**不含** `Google`/`Analytics` 这种被空格拆开的碎片。

### 3.3 页眉/邮箱噪声不入关键词（见 Issue #33/#41）
- **JD**：`新媒体运营实习生（base 北京海淀，日薪 150）。岗位职责：会用 Excel 与 SQL，数据敏感。投递方式：简历发 hr@example.com`
- **预期**：`keywords` 只含能力词（`Excel, SQL, 数据敏感`），**不含** `北京海淀`、`日薪`、`hr`、`com`。

### 3.4 中文长句片段不入选（见 Issue #41 平衡）
- **JD**：`岗位职责：负责信息流投放账户搭建与日常优化；会用 Excel 与 SQL`
- **预期**：`keywords` 不含超过 8 字的中文长句片段（如「负责信息流投放账户搭建与日常优化」）。

## 4. 数字与日期处理

### 4.1 日期不当成果（曾经把日期写成成果，见 Issue #36）
- **经历**：`在社团做公众号`
- **JD**：`运营实习生：数据分析`
- **followups**：`[{"question":"这段经历带来的可量化结果是多少？","answer":"从 2023.06 到 2023.09 涨粉 300 人"}]`
- **预期**：`rewritten` 只出现 `300 人`，**不含** `2023.06`、`2023.09`。

### 4.2 四位数阅读量不被误判为年份（回归保护）
- **followups answer**：`6 篇，阅读量 1200，平均 400，涨粉 80`
- **预期**：`1200` 完整保留（不能被当成 2023 那种年份删掉）。

### 4.3 答案无阿拉伯数字时不卡死（曾经死胡同，见 Issue #38）
- **followups answer**：`涨了大概几百人`（中文概数，无阿拉伯数字）
- **预期**：`rewritten` 保留「待补充」占位，**且** `questions` 仍有追问（如「能否补充更精确的数字…」），用户有补充入口。

---

## 5. 中文词完整性（曾经被误剥）

### 5.1 「校对/对账/对接」不被剥半（曾经变「校」，见 Issue #42）
- **经历**：`负责文案校对`（也可换 `负责对账`、`负责对接`）
- **预期**：`rewritten` 完整保留「校对」二字，**不是**「主导文案校」。

### 5.2 句首「对」仍正常剥（回归保护）
- **经历**：`对投放效果负责，优化 ROI`
- **预期**：句首「对」被剥除，`rewritten` 不以「主导对投放…」开头。

---

## 6. 限流（设计行为，非 bug）

- 同一出口 IP 30 次/小时；超限返回 429 + `Retry-After`。
- 文案应为「已达当前网络出口的用量上限（校园网/公司网下与同网用户合并计算）…」，**不是**「请求过于频繁」（Issue #24）。
- 提示：本机自测时，你与同机其他人共享额度；测试被 429 拦下可重启 `npm start` 重置计数。
